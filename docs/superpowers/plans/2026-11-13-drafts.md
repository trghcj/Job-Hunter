# Cover Letter and Resume Tips (Phase 6) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On a job's draft page, Gemini writes a 200–250 word cover letter and 3–5 resume tips from the user's profile; the user can edit, save, copy and redo it.

**Architecture:** `llm/client.py` gets the draft prompt and a strict reply parser, and `GeminiClient.draft()` shares one HTTP helper with `review()`. A new `drafts.py` holds the logic, with no web code: visibility, profile, the daily limit per user (IST day), and an upsert into a new `drafts` table, plus a `draft_usage` table for counting. `UserStore` wraps it, and three routes plus `draft.html` and `draft.js` make up the page.

**Tech Stack:** Python 3.13, FastAPI/Jinja2, SQLAlchemy 2 + Alembic, httpx, pytest, ruff.

**Spec:** `docs/superpowers/specs/2026-11-13-drafts-design.md`

## Global Constraints

- **Limits:**
  - `DAILY_LIMIT = 10` new drafts (Write or Redo) per user per IST day.
  - Save edits never counts.
  - An attempted call counts even when it fails.
- **What goes to Gemini:**
  - The profile only as `profile.for_llm(text)`, so never its first line.
  - The job description cut to `MAX_DESCRIPTION` (3000) and labeled untrusted.
- **Reply limits:**
  - Letter at most 3000 chars; an empty letter is an error.
  - Tips: strings only, whitespace collapsed, each at most 200 chars, at most 5. Zero tips is allowed.
  - A saved, edited letter is cut to 6000 chars.
- **Copy, used verbatim:**
  - "Upload your resume on Settings first."
  - "Daily draft limit reached, try again tomorrow."
  - "Couldn't write a draft right now, try again later."
  - "AI can make mistakes. Check every fact before you send it."
  - "No tips this time."
- **Display:** everything as plain text (autoescape, never `|safe`). Times use the `ist` filter.
- **Security:**
  - Every query on `drafts` and `draft_usage` filters by `user_id`.
  - The job must pass `pipeline.visible_to(user_id)`.
  - Errors log only the class and message, never a reply body or the key.
- **CSP:** the CSP has no inline scripts (`script-src` defaults to `'self'`), so the Copy button and the Redo confirm live in `static/draft.js`, not in `onclick`.

## Review Focus

1. **Redo after editing:** the confirm must fire, and a failed Redo must leave the edited letter as it was. Tested in Task 2 (`test_failed_redo_keeps_old_draft`) and Task 3 (`test_redo_button_has_confirm`).
2. **A job ad trying to inject HTML or instructions:** the letter shows escaped. Tested in Task 3 (`test_letter_html_escaped`), and the prompt labels the job untrusted in Task 1.
3. **IST day boundary:** a call at 23:59 IST and one at 00:01 IST are different days, even though both fall on the same UTC date. Tested in Task 2 (`test_limit_resets_on_ist_day`).
4. **Another user's private job or draft:** 404, and no draft is created. Tested in Task 2 (`test_other_user_cannot_see_or_save`) and Task 3 (`test_unknown_job_404`).
5. **No API key on Render:** the error message shows and nothing is counted. Tested in Task 3 (`test_no_client_shows_error_without_counting`).

### Task 2: Drafts tables and logic

**Files:**
- Modify: `src/jobhunter/db.py`
- Create: `alembic/versions/0008_drafts.py`, `src/jobhunter/drafts.py`
- Test: `tests/test_drafts.py`

**Interfaces:**
- Consumes: `Draft`, `JobForReview`, `LLMClient`, `LLMError` (Task 1); `profile.load_profile`, `profile.for_llm`; `pipeline.visible_to`, `pipeline.IST`.
- Produces:
  - **Tables** (`db.py`):
    - `DraftRow`, table `drafts`: `user_id` uses `_user_id(primary_key=True)`; `job_id` is a BigInteger FK to `jobs.id` with on delete cascade, part of the primary key; `letter` Text not null; `tips` JSONB not null; `created_at` and `updated_at` are timestamptz not null.
    - `DraftUsage`, table `draft_usage`: `user_id` uses `_user_id(primary_key=True)`; `day` Date primary key; `calls` Integer not null, server default `"0"`.
  - **In `drafts.py`:**
    - constants `DAILY_LIMIT = 10`, `MAX_EDIT = 6000`, `NO_PROFILE`, `LIMIT_REACHED`, `FAILED` (the copy from Global Constraints);
    - `class DraftError(ValueError)` and `class JobNotFound(DraftError)`;
    - `@dataclass(frozen=True) SavedDraft(letter: str, tips: tuple[str, ...], created_at: datetime, updated_at: datetime)`;
    - `make_draft(session, user_id: int, job_id: int, client: LLMClient, now: datetime) -> SavedDraft`;
    - `load_draft(session, user_id, job_id) -> SavedDraft | None`;
    - `save_letter(session, user_id, job_id, letter: str, now) -> bool`;
    - `used_today(session, user_id, now) -> int`.

- [ ] **Step 3: Implement.**
  - Add the models to `db.py`.
  - Add migration `0008_drafts.py` (revision `"0008"`, down_revision `"0007"`, same header style as 0007): `op.create_table` for both tables, with user_id FK to `users.id` on delete cascade (copy how 0005/0006 declare user FKs), and drop both in the downgrade.
  - **`make_draft`, in this order:**
    1. `select(Job).where(Job.id == job_id, visible_to(user_id))`, or raise `JobNotFound`;
    2. `load_profile`, or raise `DraftError(NO_PROFILE)`;
    3. if `used_today >= DAILY_LIMIT`, raise `DraftError(LIMIT_REACHED)`;
    4. upsert-increment `draft_usage` for `now.astimezone(IST).date()` (`insert ... on_conflict_do_update`, as in `review.py`) and `session.commit()`;
    5. call `client.draft(for_llm(profile.text), JobForReview(...))`; on `LLMError`, log `type(exc).__name__` plus the message at warning level and raise `DraftError(FAILED)`;
    6. upsert `drafts`: on conflict replace letter, tips, `created_at` and `updated_at` with `now`; then commit and return.
  - **`save_letter`:** an update filtered by user and job (strip, cut to `MAX_EDIT`, set `updated_at`); commit; return `rowcount == 1`.
